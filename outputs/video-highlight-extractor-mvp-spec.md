# 通用视频精华片段提取器 MVP 规格

## Problem Statement

用户会从手机、运动相机、无人机或其他设备积累大量视频素材。原始素材可能包含走动、失焦、遮挡、重复和无事件画面，人工逐条观看并剪辑成本很高。

本次验证素材目录包含 3 个 MP4 文件，总大小约 7.3GB，总时长约 13 分 15 秒。视频主要为 2688×1512 的 HEVC 视频并带 AAC 音频。素材应保持原位，分析过程不能修改或覆盖原片。

用户希望在每次运行时输入一段自然语言筛选要求，例如“保留宝宝表情清晰、动作完整、和家人互动的片段”或“保留风景变化明显、画面稳定、适合旅行回忆的片段”。系统根据本次 Prompt 从多个素材中找出符合要求的时间区间，并允许人工确认、调整和导出。宝宝视频只是当前验收样本，不是产品的领域限制。

## Solution

构建一个与具体素材类型和主题无关、本地优先的视频精华片段提取工具，分为四个阶段：

1. 扫描素材并建立可增量复用的本地索引。
2. 对视频进行低成本预清洗和抽样，不把完整原片直接提交给模型。
3. 调用可替换的视觉模型，根据用户在本次运行中输入的 Prompt 对带有时间戳的候选窗口评分和打标签。
4. 通过本地网页确认候选片段，导出精选 MP4、结构化时间段 JSON，以及后续可接入剪辑软件的交换格式。

MVP 的最高测试接缝是一次完整的“素材目录 + Prompt → 候选片段清单”分析流程。网页确认和导出只消费这个清单，不与具体视觉模型耦合。这样可以使用确定性的假模型测试管线，也可以在配置模型密钥后对真实素材进行质量验证。

## User Stories

1. 作为素材整理者，我希望一次选择一个素材目录，以便分析多条相关视频。
2. 作为素材整理者，我希望系统识别视频的时长、分辨率、编码、帧率和音频信息，以便在分析前确认素材有效。
3. 作为素材整理者，我希望系统记录素材校验值，以便重复运行时复用已有索引。
4. 作为素材整理者，我希望系统只在本地生成缩略图、代理视频和分析数据，以便避免复制和破坏原始素材。
5. 作为素材整理者，我希望系统自动标记黑屏、严重失焦、严重抖动、长时间静止和重复画面，以便降低模型分析量。
6. 作为素材整理者，我希望在每次运行时输入自然语言 Prompt，以便用同一套工具筛选家庭、旅行、宠物、运动、活动或其他主题的视频。
7. 作为素材整理者，我希望 Prompt 可以同时描述保留条件、排除条件、目标时长和排序偏好，以便精确控制筛选结果。
8. 作为素材整理者，我希望模型根据当前 Prompt 返回与主题相关的标签和理由，以便理解每个候选片段为什么被保留。
9. 作为素材整理者，我希望每个候选结果带有原视频名称、起始时间、终止时间、置信度和理由，以便结果可以追溯和复核。
10. 作为素材整理者，我希望相邻且内容连续的候选区间自动合并，以便避免得到大量碎片。
11. 作为素材整理者，我希望系统在候选片段前后自动保留少量缓冲时间，以便动作或事件不会被截断。
12. 作为素材整理者，我希望在网页中直接预览原视频和候选片段，以便不用打开视频编辑器就能判断结果。
13. 作为素材整理者，我希望能接受、拒绝和调整每个候选片段的起止时间，以便修正模型判断。
14. 作为素材整理者，我希望能按评分、素材文件和标签筛选候选片段，以便快速处理长列表。
15. 作为素材整理者，我希望保留人工确认结果，以便以后重新导出而无需重新分析。
16. 作为素材整理者，我希望导出精选 MP4 文件，以便直接分享到手机或导入剪映。
17. 作为素材整理者，我希望导出包含原视频和时间码的 JSON，以便保留可复现的剪辑决策。
18. 作为素材整理者，我希望导出标准剪辑交换格式，以便接入剪映、DaVinci Resolve、Premiere 或其他编辑器。
19. 作为素材整理者，我希望选择云端或本地视觉模型，以便在隐私、成本和速度之间做取舍。
20. 作为素材整理者，我希望默认只上传低分辨率代理帧或候选短片，而不是上传所有原片，以便降低隐私风险和流量成本。
21. 作为素材整理者，我希望模型不可用时仍能运行扫描、抽帧、预清洗和网页查看，以便部分能力不依赖外部服务。
22. 作为素材整理者，我希望对同一批素材使用不同 Prompt 重新分析时复用视频索引，以便快速比较不同筛选目标。
22. 作为开发者，我希望视觉模型只返回经过校验的结构化数据，以便避免自由文本时间戳导致错误剪辑。
23. 作为开发者，我希望用确定性的假模型测试从输入到导出的流程，以便没有模型密钥时也能运行自动化测试。
24. 作为开发者，我希望所有时间值使用原视频时间轴，并保留帧率和时间基信息，以便导出结果与原片准确对应。

## Implementation Decisions

- 采用本地优先架构。原片通过路径引用，不复制进项目目录，不修改原片，不删除原片。
- 以素材校验值、文件大小、修改时间和媒体元数据作为缓存失效依据。相同素材重复运行时复用索引。
- 第一轮抽样以约 1 帧/秒建立低分辨率图像索引，并默认按 30 秒、12 格生成 4×3 detail 分镜稿；macOS 优先使用 VideoToolbox 硬件解码。对于明确要求人脸的 Prompt，可先用 Apple Vision 高召回检测减少无脸分镜格子，分镜稿只用于降低视觉分析量和定位候选格子，不作为最终边界判断依据。
- 对分镜稿命中的格子扩展为候选时间窗口，再按不重叠的 4 秒瓦片去重后进行二次加密抽样，使用更高采样率检查表情、动作和事件边界，避免遗漏一秒内发生的快速动作。
- 视觉 Agent 以单个 batch 为调度单位，最多两路并行，禁止把多个 batch 合并为一个超大视觉上下文。
- 第一轮视觉 Agent 接收带有稳定分镜稿 ID、格子编号和时间映射的分镜稿，返回命中的格子集合；第二轮视觉 Agent 接收带有稳定窗口 ID 和时间戳的样本，只能返回窗口 ID、标签、评分和保留理由，不允许直接自由生成时间戳。
- 时间区间由本地程序根据窗口 ID 映射生成，再进行排序、相邻合并、最短时长约束、缓冲扩展和边界裁剪。
- 模型输出使用版本化 JSON 契约。核心字段包括素材 ID、窗口 ID、保留状态、评分、标签、理由和模型版本；缺少必填字段或字段类型错误时整批结果进入错误状态，不静默继续。
- Prompt 是每次运行的一级输入，不固化宝宝、旅行、宠物或其他领域规则。系统将 Prompt 拆解为保留条件、排除条件、单段目标时长、重复镜头处理方式和排序偏好；第一版不做自动学习用户偏好。
- Skill 的职责是把用户自然语言请求转换成一次可复跑的分析运行，并调用领域无关的扫描、抽样、分析、确认和导出能力。视频处理脚本不应依赖宝宝、家庭或某个相机品牌的字段。
- 模型接入采用适配器接口，至少支持确定性的假模型和一个多模态模型实现。没有有效模型配置时，仍允许完成扫描、抽帧、预清洗和网页确认的演示流程。
- 远程模型默认只接收压缩代理帧、联系表或候选短片。上传原片必须是显式配置，并在运行报告中记录上传范围。
- 音频在索引阶段保留；第一版可提取语音转写和基础音频事件，但音频不是候选结果生成的唯一依据。
- 使用本地网页作为人工确认层。网页只修改候选结果状态和起止时间，不重新写入视觉分析结果。
- 导出精选片段时优先保证时间边界准确，必要时重新编码；不以可能落在关键帧上的快速复制为默认策略。
- MVP 首先输出精选 MP4、片段 JSON 和可读的运行报告。FCPXML/EDL 作为标准交换格式的第二阶段输出；直接生成剪映草稿文件不纳入第一版，因为其本地资源 ID、模板依赖和版本兼容性不稳定。
- 所有运行产物放在独立的运行目录中，目录包含素材清单、抽样索引、模型响应、人工确认结果和导出文件，便于复盘和重新导出。
- 用户提供的真实目录只作为外部测试夹具，通过命令行参数传入，不将 7.3GB 素材加入版本控制或复制到仓库。

### MVP 分阶段交付

1. **素材扫描和索引**：完成视频发现、元数据解析、校验值、缓存和抽样帧生成。
2. **预清洗**：完成黑屏、模糊、静止、重复和不可读素材的标记，不直接删除素材。
3. **候选分析**：完成 Prompt 配置、窗口构建、假模型、模型适配器和结构化结果校验。
4. **人工确认**：完成本地网页预览、接受、拒绝、调整时间和保存确认结果。
5. **导出**：完成精选 MP4、片段 JSON 和运行报告；使用标准交换格式验证导入能力。
6. **真实素材评估**：使用用户提供的 3 个文件运行一次，记录处理耗时、候选数量、漏选和误选样例，作为后续 Prompt 和模型调整依据。

## Testing Decisions

- 测试外部行为和数据契约，不测试具体库的内部实现。
- 使用短的合成视频作为自动化测试夹具，覆盖多个场景、黑帧、重复帧、不同音频状态和可预期的时间边界；不在单元测试中反复读取 7.3GB 真实素材。
- 使用用户提供的真实目录做一次端到端冒烟测试，验证三条视频都能被扫描、索引和生成运行报告，并确认原片的大小和校验值未变化。
- 测试媒体扫描能正确解析 HEVC、AAC、2688×1512 分辨率、时长和多流 MP4，并能对不可读文件给出可见错误。
- 测试缓存命中时不重复生成抽样帧，素材校验值变化时只使对应资产失效。
- 测试预清洗只产生标记和评分，不删除输入文件；质量阈值变化后能够重新计算标记。
- 测试窗口生成能把采样帧映射回正确的原视频时间，能够处理文件起点、文件终点、重叠窗口和相邻窗口。
- 测试模型响应校验能拒绝缺少素材 ID、窗口 ID、评分或时间相关字段的结果，并能保存可诊断的错误信息。
- 测试候选合并、缓冲扩展、最短时长和最大时长规则，确保不会产生负数时间、超出视频时长的时间或倒序时间。
- 测试人工确认能接受、拒绝和修改候选，并在重新打开运行报告后恢复相同状态。
- 测试导出的精选 MP4 可播放、包含音频、时长与确认后的区间一致；原视频编码差异不影响播放。
- 测试 JSON 能被独立解析，并包含运行 ID、素材校验值、原始时间区间、最终时间区间、模型信息和人工状态。
- 测试没有模型密钥时，扫描、预清洗、假模型和网页确认仍可完成；模型调用错误不会丢失已生成的索引。
- 测试远程模式只读取允许上传的代理资产，并在报告中记录模型提供方、模型名和上传模式。

## Out of Scope

- 第一版不直接生成或修改剪映私有草稿数据库和模板资源。
- 第一版不自动为视频配乐、生成字幕、生成旁白、调色、稳定画面或做复杂转场。
- 第一版不训练任何特定人物、物种、场景或主题的专属模型，也不保存人脸识别身份信息。
- 第一版不自动从所有历史素材中长期学习家庭成员偏好。
- 第一版不支持手机端直接上传、后台云端队列和多用户协作。
- 第一版不承诺完全替代人工确认；AI 结果定位为候选片段推荐。
- 第一版不以每分钟 60 格分镜稿作为最终剪辑边界，也不把完整原视频默认上传到第三方服务。
- 第一版不处理所有相机厂商的私有元数据，只保证常见 MP4 视频流能被扫描和导出。

## Further Notes

- 当前宝宝视频样本适合做第一轮端到端验证：3 个文件、约 13 分 15 秒视频、约 7.3GB 存储占用。它足以暴露 HEVC 解码、抽帧速度、音频处理和候选区间合并问题，但只代表一个领域样本，不能作为通用模型效果的充分证明。
- 通用性验收至少需要使用两类不同 Prompt 运行同一批素材，并补充一个非宝宝主题的素材集，例如旅行、宠物、运动或活动记录。宝宝 Prompt 只作为示例输入，不进入核心代码默认值。
- 第一次真实运行应保留模型原始响应、抽样缩略图和人工修改记录。后续可以把“误选”和“漏选”整理成小型评测集，用于比较不同模型和 Prompt。
- 推荐先采用命令行启动分析、浏览器打开本地确认页的形式，不先做桌面应用。这样可以把核心管线和后续剪映适配解耦。
- 剪映适配应在标准 JSON 和精选 MP4 已稳定后单独验证：先确认当前剪映版本能接受的交换格式；如果无法稳定导入，再以一个固定模板的样例草稿为基准开发资源替换适配器。
- 本规格没有发布到外部 issue tracker，因为当前工作区未配置可用的 issue tracker 接口；本文件作为当前 MVP 的版本化规格和后续实现依据。
